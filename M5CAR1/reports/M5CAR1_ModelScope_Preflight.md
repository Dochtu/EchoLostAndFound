# M5-C-A-R1 魔搭（ModelScope）平台试运行前置核实

**本轮未执行任何真实调用、未登录、未部署、未创建或修改创空间、未消耗魔粒。**
本文只整理"要跑真实模型必须先确认什么"，并给出可直接执行的 5 次请求预检方案。

来源：ModelScope 官方文档与帮助页（含 `api-inference` 文档、创空间文档、魔粒/用量页），
以及本轮本地代码事实。凡是官方未写明的，一律标 **待确认**，不做推测性断言。

## 1. 官方已明确的事实

| 事实 | 内容 | 对本项目的影响 |
| --- | --- | --- |
| API Base URL | `https://api-inference.modelscope.cn/v1`（OpenAI 兼容，POST `/v1/chat/completions`） | `LLM_BASE_URL` 不带尾斜杠，代码自行拼 `/chat/completions` |
| 鉴权 | `Authorization: Bearer <ModelScope Token>` | 现有适配器已按此发送；密钥只来自服务端环境变量 |
| 免费额度 | API-Inference 被文档描述为免费、**不承诺 SLA**、限流动态调整且未公布 QPS | 不能当作可依赖的线上通道；失败路径必须仍然可玩（已实现） |
| 付费通道 | 魔粒（0.5 / 1 / 2 魔粒/次，对应轻量/主流/旗舰模型档位） | 预算单位是"次"，与 token 不是同一量纲 |
| Token↔魔粒 换算 | **官方未公布** | 本轮代码不写任何换算，记账只用 token |
| 创空间磁盘 | 默认磁盘数据在每次重启后丢失；只有 `/mnt/workspace` 是持久卷 | 台账与哨兵必须放 `/mnt/workspace` |
| 持久卷边界 | `/mnt/workspace` 在转移/改名后会丢失；Docker 构建期不可用 | 平台侧仍不能视为可靠持久化 |
| 端口 | Docker 创空间固定暴露 **7860**（容器内 8080 被占用） | `app.server_entry` 默认 7860，可直接匹配 |
| 保留头 | `Authorization`、`X-modelscope-*`、`X-studio-*` 由平台占用，官方要求后端不要使用 | 应用层令牌用自定义头 `X-Dialogue-Token`（已实现） |
| 模型 ID | `owner/name`；带 `:Provider` 后缀会路由到第三方供应商 | `LLM_MODEL` 只写 `owner/name`，不要带后缀 |

## 2. API Base URL 与模型 ID 的核实方法（零消耗）

| 目标 | 方法 | 判定 |
| --- | --- | --- |
| Base URL 正确 | 不联网核对：Base 必须形如 `https://<host>/v1`，代码会拼 `/chat/completions` | 用 `curl -s https://api-inference.modelscope.cn/v1/chat/completions -o /dev/null -w '%{http_code}'` 应得 401 而不是 404（**401 也计为一次失败鉴权，需确认是否会扣量**） |
| 模型 ID 存在 | `GET https://modelscope.cn/models/{owner}/{name}.md` → 200 存在 / 404 不存在 | 不消耗推理额度 |
| 模型详情 | `GET https://modelscope.cn/api/v1/models/{owner}/{name}` | 返回 JSON 元信息 |
| 是否第三方路由 | 检查 ID 是否含 `:` | 含则跳过（会走外部供应商，计费与行为不同） |

## 3. API Key 的配置位置（服务端）

| 项 | 要求 |
| --- | --- |
| 存放 | 仅环境变量 `LLM_API_KEY`（本地 `.env` 不入库；平台用"环境变量/密钥"功能注入） |
| 禁止 | 不写入 `ms_deploy.json` 的 `environment_variables`（该文件随 git 走，等于公开） |
| 禁止 | 不写入代码、配置正文、日志、客户端资源；`.env.example` 只有占位值 |
| 校验 | 启动后 `GET /api/v1/health` 不得回显密钥；本轮测试 `test_fake_key_never_appears_in_the_response` 已固定 |
| 轮换 | 失效即替换环境变量并重启；台账 `epoch` 不受影响 |

## 4. 计费方式与魔粒余额核对

| 项 | 怎么做 |
| --- | --- |
| 余额 | 魔粒用量页 `https://modelscope.cn/magicube/usage?tab=earn`；短期额度 24h、长期额度 90d 有效 |
| 单次消耗 | 记录预检请求前后的余额差；同时记录本服务 `health.ledger.tokens_used` 与 `global_used` |
| 是否按 token | **待确认**：官方只按"次"标价，未公布 token 折算 |
| 免费额度是否也扣魔粒 | **待确认**：文档称免费、限流；与魔粒页的"每次扣减"描述存在张力 |
| 失败请求是否计费 | **待确认**：需用 1 次无效请求（非存在模型）与 1 次超时观察余额变化 |
| 建议 | 首轮 5 次请求逐次记录"时间 / 请求类型 / HTTP 码 / usage / 余额变化"，见第 8 节 |

## 5. 平台持久化能力（上线阻塞项 1）

| 结论 | 依据 | 影响 |
| --- | --- | --- |
| 默认磁盘不持久 | 官方："每次创空间重启时，磁盘上默认写入的数据都会丢失" | SQLite 台账放默认磁盘 = 每次重启预算归零 |
| 仅 `/mnt/workspace` 持久 | 官方持久卷说明 | 台账与哨兵必须放这里 |
| 转移/改名后丢失 | 官方说明持久卷不随转移保留 | 平台侧仍不能证明"独立可信位置" |
| 单副本 | 单容器、单进程 | 与本项目 `workers=1` 假设一致 |

**仍未证明**：`/mnt/workspace` 是否会被同时回滚（数据库+哨兵一起），以及是否有平台侧外部审计。
因此在模型侧上线前，本项目把"共同回滚保护"标记为**未证明**。

## 6. 反向代理与客户端地址（上线阻塞项 2）

| 项 | 现状 |
| --- | --- |
| 平台是否透传 `X-Forwarded-For` | **官方未文档化** |
| 是否有固定代理网段 | 未公布（容器网络通常是 172.16.0.0/12 或 10.0.0.0/8，但未确认） |
| 本轮决定 | `TRUSTED_PROXY_CIDRS` 保持为空；`app.server_entry` 固定 `proxy_headers=False`；客户端地址 = 代理地址 |
| 后果 | 所有玩家共用少量"客户端桶"，需要把 `NEW_SESSION_RATE_*` 调紧以限制撞库式建会话 |
| 验证方案 | 部署后用外部机器发 `X-Forwarded-For: 1.2.3.4`，对比 health/日志里记录的客户端地址；若地址不随头变化，说明平台不透传或应用正确忽略 |

## 7. 真实调用失败后的立即回滚

1. 创空间页面 → **停止/下线** 服务（避免继续消耗）；
2. 把 `APP_ENTRY_MODE=mock`（或 `MODEL_PROVIDER=mock`）写回环境变量并重启；
3. 若代码版本有问题：`git revert` 到 `4c51712c362e18bfcf9215cea766e61731773c74` 后重新部署；
4. 核对 `health.ledger`：`tokens_used`、`global_used`、`epoch_fingerprint` 与下线前一致；
5. 若台账可疑：**不要** `ledger_admin reset`，保留现场并上报（自动重置会掩盖故障）。

## 8. 首轮真实模型预检：不超过 5 次请求

前提：用户明确授权 + 魔粒余额已核对 + 密钥仅注入到服务端。

| # | 请求 | 目的 | 成功信号 | 失败处理 |
| --- | --- | --- | --- | --- |
| 1 | 自由对话："只回复四个字：回声测试" | 验证通道、鉴权、模型 ID | `source=external_model`、`provider.is_synthetic=false`、返回文本含"回声测试" | 4xx → 记录 code 后停止 |
| 2 | 同一句话再发一次（新 request_id） | 验证非缓存、限流表现 | 两次 `usage` 均为非零且不完全相同 | 若返回完全相同文本且 usage 恒为 0 → 判定为缓存/代理，标注待确认 |
| 3 | 中文语义回合："站台那晚的灯是谁摆好的？" | 验证中文与角色边界 | 回复符合老周口吻且不含未解锁事实 | 含未解锁事实 → 立即停止并回滚 |
| 4 | 不存在的模型 ID | 验证错误处理 | 结构化 4xx，health `model_status=upstream_error`，无重试 | 5xx 或无限等待 → 记录并停止 |
| 5 | 备用（可选）：一次超时/中断 | 验证超时与保守计费 | `fallback`、`global_used+1`、`tokens_used` 增加预留额 | — |

每次请求后立即记录：`health.ledger`、上游 `usage`、魔粒余额差、耗时可复算的时间戳。

## 9. 待确认清单（必须由用户/平台侧回答）

1. 免费额度与魔粒扣减的真实关系（是否每次调用都扣）。
2. 失败请求（4xx/5xx/超时）是否计费。
3. `X-Forwarded-For` 是否透传、代理网段范围。
4. `/mnt/workspace` 的持久化边界与是否支持多副本/备份。
5. 是否提供平台侧访问日志（用于事后核对预算）。
6. 创空间冷启动/休眠策略（影响首请求超时设置）。
7. `ms-` Token 的官方格式（当前扫描规则为启发式）。
8. 是否允许公开展示（当前保持私有）。
9. 计费档位（0.5/1/2 魔粒）对应的模型清单与 QPS。
10. 平台是否允许携带自定义 `Authorization`（文档要求勿用）。

## 10. 结论

真实模型"能跑"与"能上线"是两件事。本轮已把**服务端侧**的必要条件做完并有测试；
平台侧仍有两项未证明：**持久化（含共同回滚）** 与 **代理拓扑**。
在这两项被平台方明确回答或实测确认之前，本项目对真实模型上线保持**阻塞**状态。
