### 二、游戏核心创意

**一句话介绍：**

在一座即将关闭的旧火车站，你成为最后一名夜班失物管理员。每一件遗失物品都承载着一段记忆，而每个人对同一件往事的描述都不一样。你必须通过自由对话、探索和证据推理，找出被遗忘的真相。

**核心宣传语：**

每件失物都有主人，但没有一个人记得全部真相。

#### 2.1 世界观

游戏发生在一座虚构的中国小城——青禾镇。

青禾火车站即将关闭，你临时接替最后一班夜班工作。

某个雨夜，你在整理仓库时发现了三件长期无人认领的物品：

- 一块停在21:17的旧怀表。
    
- 一盘没有播放完的录音带。
    
- 一张没有姓名的旧车票。
    

这些物品都与十二年前的一场暴雨夜有关。

当时，一班末班列车临时停运，几个人在车站发生了交集。多年过去，他们对那一夜的记忆却完全不同。

有人记得自己帮助过别人，有人认为自己被抛弃，也有人一直隐瞒着某个承诺。

你需要通过与他们交流、调查车站、整理证据，逐步拼出完整事件。

#### 2.2 核心创新

游戏最大的创新不是让 AI 生成更多对话，而是：

1. NPC 拥有独立的长期记忆。
    
2. NPC 具有自己的性格、目标和秘密。
    
3. 不同 NPC 对同一事件有不同记忆。
    
4. NPC 会记住玩家之前的提问、承诺和行为。
    
5. 玩家可以使用收集到的证据质疑 NPC。
    
6. 玩家不同的处理方式会改变人物关系和最终结局。
    

游戏中的事实由开发者预先设计，AI 负责根据人物记忆和玩家行为生成符合设定的互动。

因此，NPC 可以有偏见、误解甚至故意隐瞒，但不能随意创造新的案件事实。

### 三、游戏角色设计

第一版控制在4名核心人物以内，避免角色过多导致记忆管理和美术成本失控。

#### 角色一：老周

身份：退休车站工作人员。

性格：

- 说话直接。
    
- 不喜欢别人追问过去。
    
- 对车站有很深的感情。
    
- 不善于表达自己的情绪。
    

秘密：

十二年前的暴雨夜，他曾经修改过一份车站记录，原因并不是为了谋取利益，而是想保护当时的一名乘客。

AI 特征：

- 对车站布局和当年的工作流程非常熟悉。
    
- 对自己参与的事情记忆清晰。
    
- 遇到敏感问题会回避。
    
- 如果玩家之前帮助过他，他会逐渐愿意透露信息。
    

#### 角色二：林遥

身份：多年后重新回到青禾镇的女性。

性格：

- 敏感。
    
- 不容易相信别人。
    
- 对过去有强烈的执念。
    

秘密：

她一直认为十二年前有人没有履行约定，因此多年无法释怀。

AI 特征：

- 对涉及家庭和承诺的话题反应明显。
    
- 会记住玩家之前给予她的承诺。
    
- 玩家如果反复质疑她，她可能拒绝继续交流。
    
- 玩家表现出理解后，她会主动分享过去的细节。
    

#### 角色三：许澄

身份：曾经在青禾镇生活的年轻音乐爱好者。

性格：

- 比较开朗。
    
- 喜欢讲故事。
    
- 有时会回避严肃话题。
    

秘密：

录音带中存在一段被覆盖的声音，而他知道这段录音与当年的事件有关。

AI 特征：

- 记忆存在一定偏差。
    
- 对音乐、声音相关问题非常敏感。
    
- 会记住玩家发现的录音线索。
    
- 在证据充分时，愿意修正自己之前的判断。
    

#### 角色四：玩家

身份：青禾车站最后一名夜班失物管理员。

玩家没有预设的复杂背景，主要通过调查和对话推动故事。

### 四、核心玩法设计

游戏采用五步循环：

**探索 → 对话 → 收集证据 → 推理 → 作出决定**

#### 4.1 探索系统

玩家可以在三个主要场景中探索：

1. 失物招领处。
    
2. 候车大厅。
    
3. 站台。
    

每个场景存在可交互物品。

例如：

- 旧照片。
    
- 怀表。
    
- 录音带。
    
- 车票。
    
- 维修记录。
    
- 车站公告。
    

点击物品后，玩家可以查看物品信息，发现隐藏细节，并将其添加到证据档案。

#### 4.2 自由对话系统

这是整个游戏最重要的机制。

玩家可以自由输入问题，而不是只能点击固定选项。

例如，玩家向老周询问：

“十二年前那场暴雨，你是不是也在车站？”

老周可能回答：

“我在这里工作了二十多年，那天当然也在。”

玩家继续问：

“为什么那天的发车记录少了一页？”

老周可能回避：

“你一个新来的，怎么这么喜欢翻旧账？”

如果玩家找到了对应的维修记录，再次询问时，他的回答可能发生变化。

这里的关键在于：

AI 必须结合 NPC 的人格、记忆、已发现证据以及玩家历史行为来生成回答。

#### 4.3 记忆系统

每个 NPC 都拥有三类记忆：

- 短期记忆：最近几轮对话。
    
- 长期记忆：玩家之前的重要行为、承诺和关系变化。
    
- 事件记忆：NPC 对十二年前事件的个人认知。
    

例如：

玩家第一次询问林遥时，她拒绝谈论自己的家庭。

玩家之后找到了录音带，并帮助她确认了其中的一段声音。

再次交流时，她会记住玩家曾经帮助过她，并主动谈起过去。

这才是 AI 智能 NPC 的核心价值。

#### 4.4 证据推理系统

玩家可以打开证据板，将不同线索进行关联。

例如：

- 证据A：怀表停在21:17。
    
- 证据B：维修记录显示21:17发生过停电。
    
- 证据C：老周声称当时站台一直有照明。
    

玩家可以将这些证据组合，发现人物陈述之间的矛盾。

然后选择向 NPC 出示证据。

NPC 会根据自己的知识和性格作出反应。

推理判定由游戏逻辑完成，而不是完全交给大模型。

#### 4.5 结局系统

结局不应该只有正确和错误。

玩家最后需要决定如何处理收集到的物品和故事：

- 归还：让物品回到它真正的主人手中。
    
- 封存：尊重某些人物不愿公开的记忆。
    
- 公开：将事件整理成车站的历史档案。
    

不同决定会影响人物之间的关系和结尾演出。

### 五、三个章节的具体设计

目标总时长：30～40分钟。

#### 第一章：停走的怀表（约8分钟）

主要任务：

找出怀表真正的主人。

玩法：

1. 检查怀表外观。
    
2. 发现怀表背面刻有一组特殊数字。
    
3. 询问老周。
    
4. 询问林遥。
    
5. 找到车站维修记录。
    
6. 组合证据。
    
7. 决定将怀表交给谁。
    

本章主要展示：

- NPC自由对话。
    
- 人物记忆。
    
- 物品探索。
    
- 证据关联。
    

#### 第二章：没有寄出的录音带（约8分钟）

主要任务：

弄清录音带中被覆盖的声音。

玩法：

1. 检查录音带。
    
2. 找到播放设备。
    
3. 通过录音片段获取信息。
    
4. 与许澄交流。
    
5. 向林遥询问相关记忆。
    
6. 发现两个人对同一段经历的描述不同。
    
7. 使用证据进行交叉验证。
    

本章主要展示：

- 多人物互动。
    
- 记忆偏差。
    
- NPC之间的认知差异。
    
- 证据驱动的动态对话。
    

#### 第三章：没有名字的车票（约12分钟）

主要任务：

还原十二年前暴雨夜发生的完整事件。

玩法：

1. 整理前两个章节的证据。
    
2. 重新询问老周。
    
3. 与林遥、许澄分别交流。
    
4. 找到缺失的发车记录。
    
5. 建立完整事件时间线。
    
6. 发现三个人都只记得当年事件的一部分。
    
7. 作出最后的决定。
    

本章主要展示：

- 长期记忆。
    
- 多人物关系。
    
- 跨章节状态继承。
    
- 玩家行为对结局的影响。
    

#### 时间分配

|内容|时间|
|---|---|
|游戏开场|3分钟|
|第一章|8分钟|
|第二章|8分钟|
|第三章|12分钟|
|最终结局|3分钟|
|合计|34分钟|

这34分钟应该是有实际探索、交流、推理和决策的体验，而不是靠无限聊天凑时长。

### 六、技术架构

#### 6.1 技术选型

|模块|技术|
|---|---|
|游戏客户端|Godot 4|
|游戏脚本|GDScript|
|后端|Python + FastAPI|
|大模型|支持结构化输出和工具调用的 LLM API|
|数据库|SQLite|
|记忆检索|结构化检索，后续视规模增加向量检索|
|通信|HTTP + JSON|
|版本管理|Git + GitHub|

#### 6.2 系统架构

游戏分成四个核心模块：

**A. Godot 游戏客户端**

负责：

- 场景切换。
    
- 角色显示。
    
- 物品交互。
    
- 对话界面。
    
- 证据板。
    
- 结局展示。
    

**B. NPC Agent 服务**

负责：

- 接收玩家输入。
    
- 读取 NPC 人格。
    
- 获取相关记忆。
    
- 调用大模型。
    
- 生成符合人物设定的回答。
    

**C. 记忆管理服务**

负责：

- 保存玩家与 NPC 的对话历史。
    
- 提取重要事件。
    
- 保存人物关系变化。
    
- 检索与当前问题有关的历史记忆。
    

**D. 游戏规则引擎**

负责：

- 案件真相。
    
- 证据解锁。
    
- 推理判定。
    
- NPC 信息开放条件。
    
- 结局判定。
    

特别注意：游戏规则引擎不能交给 LLM 随意控制。

#### 6.3 NPC 对话流程

玩家输入：

“你是不是知道那张车票是谁的？”

后端处理流程：

1. 根据 NPC ID 获取人物设定。
    
2. 查询该 NPC 的长期记忆。
    
3. 查询当前案件进度。
    
4. 检查 NPC 是否知道相关信息。
    
5. 构建提示词。
    
6. 调用大模型。
    
7. 验证返回结果。
    
8. 保存重要对话记忆。
    
9. 返回客户端展示。
    

#### 6.4 NPC 返回结构

要求大模型按照固定 JSON 格式返回：

```
{
  "dialogue": "那张车票我好像见过……",
  "emotion": "hesitant",
  "revealed_fact_ids": [],
  "memory_candidate": null
}
```

后端需要验证：

- 返回格式是否正确。
    
- 透露的信息是否允许。
    
- 当前 NPC 是否拥有相关知识。
    
- 是否出现与已确认事实冲突的内容。
    

不允许大模型直接修改案件真相。

#### 6.5 数据库设计

第一版建议建立以下数据表：

- players：玩家信息。
    
- cases：案件信息。
    
- npcs：人物信息。
    
- npc_memories：NPC记忆。
    
- evidence：证据资料。
    
- dialogue_logs：对话记录。
    
- player_progress：游戏进度。
    
- npc_relationships：人物关系状态。
    

先使用 SQLite，不要一开始引入 Redis、向量数据库和复杂的分布式架构。

### 七、美术与音效方案

由于团队暂时没有美术人员，建议采用：

**低饱和度、复古、带有电影感的2D插画风格。**

视觉关键词：

- 雨夜。
    
- 暖黄色灯光。
    
- 深蓝色背景。
    
- 老式火车站。
    
- 怀旧。
    
- 安静。
    
- 神秘。
    

美术资源优先级：

|资源|数量目标|
|---|---|
|主要场景背景|3张|
|NPC立绘|3张|
|NPC表情变化|每人3种|
|核心物品图|8～12张|
|UI图标|10～15个|
|关键剧情插画|3～5张|

使用 AI 生成初稿，再进行统一色彩、构图和细节处理。

建议使用固定的美术提示词模板，确保人物在不同场景中保持外观一致。

不需要制作复杂的骨骼动画。通过人物立绘、表情切换、镜头移动和场景光效，就可以形成不错的表现力。

音乐建议：

- 雨声。
    
- 火车站广播。
    
- 时钟滴答声。
    
- 轻柔钢琴。
    
- 低沉环境音。

### 九、项目验收标准

不要只以代码写完作为完成标准。

以下是项目真正需要达到的要求：

|验收项目|目标|
|---|---|
|游戏时长|30分钟以上|
|完整章节|3章|
|核心 NPC|3名|
|自由对话|支持|
|长期记忆|支持|
|证据收集|支持|
|证据推理|支持|
|多结局|至少2种|
|AI异常处理|有备用方案|
|游戏进度保存|支持|

AI质量测试：

- 准备至少50个典型测试问题。
    
- 检查人物回答是否符合人格。
    
- 检查 NPC 是否泄露未知事实。
    
- 检查历史记忆能否正确召回。
    
- 检查 NPC 是否会忘记玩家的重要承诺。
    

目标是让玩家感觉自己真的在和有独立记忆的人物交流。

---

### 十、项目范围控制

第一版明确不做：

- 3D 开放世界。
    
- 实时战斗。
    
- 多人联机。
    
- 复杂角色动画。
    
- 无限生成剧情。
    
- 大规模多 Agent 社会模拟。
    
- 完全由 AI 决定案件真相。
    

我们只做一件事：

**让玩家在一个小型、精心设计的世界中，通过与拥有长期记忆的 NPC 交流，体验传统固定对话游戏无法提供的推理和叙事体验。**

这才是整个项目最重要的竞争力。

---

### 十一、参赛展示重点

评委体验游戏时，建议按照以下顺序展示：

1. 进入车站，发现怀表。
    
2. 自由询问 NPC。
    
3. NPC 回避问题。
    
4. 玩家发现一份新的证据。
    
5. 再次询问同一个 NPC。
    
6. NPC 记得玩家之前的行为，回答发生变化。
    
7. 玩家利用证据指出矛盾。
    
8. NPC 展现不同情绪并透露新的记忆。
    
9. 玩家作出决定，展示不同结果。
    

整个过程应当让评委直观看到：

AI 不只是帮助开发者制作游戏，而是在游戏运行时直接参与了核心体验。

**最终项目目标：一款有明确推理玩法、有持续记忆的智能 NPC、有情感表达、有完整结局的 AI 原生叙事游戏。**
