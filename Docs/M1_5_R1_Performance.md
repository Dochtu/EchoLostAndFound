## 诊断

M1.5 编辑器原始 Profiler 的 25 帧中，主线程 WaitForLastPresentation.WaitForGPU 平均 10.78 ms，渲染线程 RenderShadowMaps 平均 3.89 ms。数字为跨帧的包含子项耗时，不可与父项累加。R1 对 275 个固定环境/灯具渲染器标记静态投影与静态合批，将固定点光投影切换为缓存，动态角色仍每帧投影。已有三级 LOD、共享材质和项目 SRP Batcher 沿用。三个反射探针继续使用已有配置。未更改共享 HDRP 设置，未重烘整站光照或新增遮挡烘焙数据。

M1.5 的 3590 Batches 来自 Editor；本表来自 Player 的 ProfilerRecorder。二者统计环境不同。上表 CPU/GPU 取有返回值的 FrameTiming 样本，主线程 Present 等待单列。CSV 中没有新计时结果的字段为空，每段有效样本数见 summary。

三个进程中 D3D12 环形缓冲区空间不足警告分别出现 1, 1, 1 次。单条启动警告不能定位至某一长帧。

关闭 VSync 时，GPU 平均约 15.6–17.5 ms，CPU 主线程有效工作约 3.6–3.9 ms、渲染线程约 4.1–4.7 ms。第三组静止段 GPU 时间超过 60 FPS 的 16.67 ms 帧预算。结合开启 VSync 时约 13 ms 的主线程呈现等待，现有数据支持 GPU 帧预算与呈现节奏是主要限制。Present 等待含排队和等待 GPU 的时间，与 GPU 耗时重叠。关闭同步后仍有等待，不能将所有等待都归入 VSync。重复组之间为何变慢还缺少频率、功耗和温度证据。

第三组额外的真实 Player 轨迹在 Unity Profiler 中读回 121 个帧记录。关闭 VSync 的移动样本中，主线程 DXGI.WaitOnSwapChain 的每帧累计平均 12.78 ms，渲染线程 RenderShadowMaps 为 1.86 ms，HDRenderPipelineRenderCamera 为 4.07 ms。它们分别描述交换链等待和 CPU 端渲染线程标记，并非对应 GPU pass 的独占耗时。GPU pass 的精确归因仍待硬件级 GPU 采样。
